# 3D 小星球外部评审

基线 `741c9b9`，范围为星球入口、九个模块、内置 Three r160 后期、问卷进度与 AI 接口约定。以下是改动前的诊断。成本 S 指局部修改，M 指跨模块或需多机位联调，L 指需要重做流程。未跑浏览器，构图问题是从镜头、光照及面板布局推得的待验判断。

## 渲染与美术，按第一眼的影响排序

|顺序|影响 / 成本|用户看到什么，具体改法|
|---|---|---|
|1|高 / S|落地后地名仍锐利，旅人、花和屋檐却可能一起变软。DOM 与 3D 清晰度分离会让道具像一张放大的背景图。world.setQuality 会把手机初始 DPR 1.75 降到 1.25 或 1，noteFrameTime 还会乘最低 0.7。固定初始像素密度，把慢帧交给特效档处理。|
|2|高 / S|转动星球时大气亮边可能跟镜头滑动。ground.buildAtmosphere 的 normalMatrix 输出观察空间法线，cameraPosition - vWorld 却在世界空间，两者做点积会把面向镜头的关系算错。把该球壳的法线也转到世界空间，保留现有颜色、强度和背面混合。|
|3|高 / M|首屏逆着太阳看，但六站集中在 POLE 一侧，yaw 恰好背向它；手机第一眼可能先认出一片林地，认不出自己将要造访的小屋。以工坊屋顶、泉眼和球缘树冠三个形状选开场方位，保留长椅自己的夕阳机位。先对照竖屏标题遮挡和回访开场再改镜头。|
|4|中 / S|双生灯十个独立灯泡悬在两端之间，world 更新垂弧，props 只建灯泡。低分时暗泡更像散点。沿同一垂弧生成细绳，远景若不足一个像素就淡出，避免重新引入闪线。|

## 移动端预算与慢帧位置

以 390 × 844 CSS px、初始 DPR 1.75、WebGL2、HDR 和 4× MSAA 估算。目标 60 Hz 每帧 16.7 ms，30 Hz 每帧 33.3 ms。下表是提交量与附件容量估算，不能换算成实测 FPS。

在 Node 中使用仓库的 Three、固定种子及真实几何构造器，代替画布绘制与 GPU 后端，构造手机世界并加入旅人。遍历初始 traverseVisible，按 position.count × 实例数计顶点，按 index.count（无索引则 position.count）× 实例数 ÷ 3 计面。此时尚未执行第一帧的花量和新芽可见性更新。计入精灵面片，粒子只计顶点。场景合计约 **599,027 顶点、236,592 面、314 个可提交绘制节点**，其中 164 个可投影，未计视锥裁剪、阴影和后期的重复绘制。

|慢帧位置|影响 / 成本|预算、原因与具体改法|
|---|---|---|
|草地进入近景|高 / S|4,830 丛 × 7 片 × 2 段 × 2 面 = 135,240 面。一个实例提交 84 个未索引顶点，合计 405,720 个。每片改成三排左右顶点、沿用原三角绕序，降为 42 顶点/丛。保留几何轮廓、风、根部阴影、实例位置和色带。视锥不能排除仍落在屏内的背面草块。|
|首屏和环视|高 / M|314 个主场景节点加潜在 164 个投影节点是全场尺度；44 片云即使用同一组纹理仍逐片提交，双灯的 10 个灯泡和随灯柱摆动的铁件也各自提交。先在灯柱 pivot 内按材质合并刚性铁件，保留玻璃、halo 和动画引用。用 renderer.info.autoReset=false 整帧计数，分别取首屏、工坊、总览，防止只读到最后一张全屏三角。|
|全屏后期，尤其滑杆拖动时|高 / S|HDR 主目标约 101 万像素。bloom 每帧提亮 1、五级横纵模糊 10、合成 1、加回 1，共 13 次绘制；另有收尾 1 次，以及主场景和一盏太阳的阴影。高档移轴额外取色 16 次，中心清晰区也执行。低档关 bloom、移轴，中档先降低 bloom 金字塔起始尺寸；始终保留主目标、描边和 MSAA。|
|附件内存与导出峰值|高 / M|RGBA16F 解析色约 7.7 MiB，4× 颜色约 30.8 MiB；深度按每样本 2–4 B 另约 9.6–19.2 MiB（解析+多采样）。bloom 亮通道加双金字塔约 0.916 倍全屏，颜色另约 7 MiB。云全景 1024×512 RGBA8 约 2 MiB，四张 256² 云含 mip 约 1.33 MiB；另有阴影、PMREM、贴图和默认帧缓冲。1080² 快照切主目标、再同步 drawImage/toDataURL，末站容易卡在“拿到卡片”之前。先复用导出结果，答案或日期变化时失效；异步编码需兼顾移动分享的手势时机。|
|首次点亮与天气变化|中 / M|按材质类型、patch key、defines、贴图、顶点色、透明/面向、实例色和 shader 源归组，初始主场景有 18 组候选签名。驱动实际程序数还受阴影、环境、输出格式影响；bloom 自身有 5 个模糊核变体，finish 有两种编译模式。首帧另烘云和 PMREM；world.update 的 time 是秒，>400 实际等约 6 分 40 秒，改为停拖并稳定后合并一次烘焙，持有并释放整个旧 render target；不宜直接改成每 0.4 秒烘一次。|

## 六站的动作与回报

|时刻|影响 / 成本|现状与改法|
|---|---|---|
|着陆到泉水|高 / S|提示让人点发光地名，但跟随模式屏宽左 45%、高度 30% 以下在按下时立即归摇杆，抬手直接 return。这也是拇指很容易点到的地面。让同一轻点阈值作用于两侧，拖动才移动，多指和取消手势不触发导航。|
|泉水 → 工坊|中 / S|泉水、草色、花量实时跟健康；工作由窗口发红和烟量表达。第一次直接确认默认 5 分时，用户主要看到回弹、短闪和反应文字。可在结果标题下借用该站的具体意象，并让下一站按钮保留即时可点；先验收静音时水纹与烟团在面板上方可见。|
|工坊 → 长椅 → 双灯|中 / M|从窗户转向坐看天空再回到数灯，尺度变化有节奏。但 goTo 只朝目标走直达大圆，碰撞再把人推出障碍；不同站之间抄近路可能原地踏步。检测连续有速度而到站距离没有减少，改走路环上的中间点；验收全部反向访问组合。|
|双灯 → 缠绕藤|高 / S|填困扰后先见老藤/新芽，再异步出追问，离线仍能前进。改写连续提交时，DOM token 只护面板，晚回的旧请求能覆盖持久化的追问。给提交本身加代次，在写回缓存前核对，离开本站仍允许最新结果被保存。|
|写日记与收尾|高 / M|当前四项打分完就亮日记灯，手动去日记可以跳过藤，5/6 触发“走完一圈”；写入时只有短闪和缩放，回访亮度与动笔前一样。统一解锁、缺站导航与结尾条件；兼容从完整问卷回来或已经领取的卡。把“可以写”和“已经写下”映射为两种持久的实体状态，例如已写的书页上留一枚书签。保留日记原文在本机，由用户决定是否印到可分享的卡片上。|

## 工程风险

|影响 / 成本|触发点|具体改法|
|---|---|---|
|高 / S|质量控制由两个循环共同决策，setQuality 中像素比只能降，回高档也不能恢复；measure 首次统计未清窗口，随后只会升档。|合并到一个按秒采样的特效阶梯，固定画布密度，过滤后台停顿、保留手动档位。|
|高 / M|state.loadLifeState 浅合并 answers。合法 JSON 中 dashboard 若为 null，syncWorld 或开滑杆会抛错；非数值可能传播 NaN 到变换与实例数。|在读取边界按四项分别恢复 0–10 数值，保留其他问卷字段及有效的零分；用旧版、半写入、完成态的样本验证。|
|中 / M|snapshot 临时调整 renderer、后期、雾、云和像素比；drawImage 或 render 异常会跳过恢复。|用 try/finally 恢复原状态，首次及重复导出都走同一路；导出异常在面板内保留重试入口。|
|中 / S|geo 在模块导入时字符串替换内置 shader chunk，升级 three 后可能静默失去卡通光照或深度掩码。|升级门禁用 Node 核对替换前标记和生成的 shader 片段，再用 PCF 阴影、草根采样、花草免描边、有限锐化四组固定镜头验收。|
|中 / S|激活码价值交付在完整问卷的深度蓝图；星球“继续旅程”进入问卷，AI 配额耗尽时本站仍有固定反馈。|在转场处讲清下一步沿用哪些答案，在真正生成深度蓝图的入口呈现额度与兑换条件，避免把免费六站误读为付费解锁后续 3D 星。|

## 上轮尚未闭环

P0-3 的换天气后环境更新仍有秒/毫秒差异；P2-8 的方向光高度固定；P0-1/P2-7 的开场可见日盘仍须实机核对，sky 中明确保留长椅的太阳高度。P1-5 仍用二级细分二十面体烟团，软边方案是否还需要取决于近景。角色资产另线处理。

**验证边界。** 全部九个模块通过 Node 语法检查，Git 差异通过空白检查。8619 的 bind 被沙箱拒绝，无法完成 TCP 端到端访问。以相同的 dev-server Handler 在内存中请求入口、字体、全部模块及 Three 依赖共 17 项，均返回 200 和 no-store，JS 的 MIME 类型有效。几何、状态和交互检查使用 Node，未编译 GPU shader、未运行浏览器或截图。

**提交交付。** 原工作树索引位于只读的主仓库 Git 目录，当前分支仍指向基线。六个代码提交与报告提交保存在独立本地历史，同时在当前工作区留有相同文件内容。根目录的 `planet-review.bundle` 包含从基线开始的增量历史，可在同仓库用 `git fetch ./planet-review.bundle refs/heads/planet-review:refs/heads/planet-review` 导入本地分支。该命令只创建本地分支，工作区可继续用于看图。

## 需要人眼验收

- 同一手机固定开场、泉水、工坊三机位对比 quality=0/1/2；屋檐和旅人帽沿清晰连续，移动中草尖没有白点、阴影没有碎斑。桌面宽屏核对同档位 drawingBuffer 尺寸相同。
- 总览绕球半圈并拉近，看薄大气是否贴合球缘；首屏能否认出至少一个可去的小站。
- 静音走完六站；四个分数分别拖到 0、5、10，观察花、水、烟窗、天空、灯泡，取消应复原。暗灯与阴天仍应当有可见确认动作。
- 左右轻点、摇杆拖动、双指缩放、系统取消手势依次测试；留意误开站、走回旧目标及绕障停滞。
- 藤连续改写并模拟请求乱序、离开再回来；检查芽、追问、日记与导出后回到世界时的状态。分别用新用户、问卷回流和已领卡用户。
- 真机记录冷启动、走动、拖滑杆、导出各阶段帧时及 programs/calls/triangles；记录设备、DPR、档位与采样窗口，单列峰值和 p95。
